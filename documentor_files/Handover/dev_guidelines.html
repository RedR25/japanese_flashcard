3. Key Patterns

  • Single-source folder: src/ is the centralized location for all frontend assets and styles. The project relies on a flat source layout rather than multi-package or multi-folder structure.
  • CSS-first styling: Repository primary language is .css and the main work is editing and adding CSS files inside src/. Changes are localized to style assets rather than JS/templating.
  • Small, focused codebase: With 6 files total and 4 in src/, the pattern is minimal footprint and rapid edits — prefer small, targeted changes in src/ rather than large refactors.

4. Adding Features Checklist

  1. Create the style file in src/ as a .css file. Name the file clearly to reflect the feature (place it directly under src/ since the project uses a single source folder).
  2. Locate existing CSS entry files in src/ and add an import or merge. If there is a main stylesheet inside src/, append an @import or copy component rules into that file. If no single entry exists, place the new file alongside the other files in src/ to keep structure consistent.
  3. Keep changes minimal and isolated: add selectors scoped to the new feature to avoid global collisions; use class selectors rather than relying on element selectors when adding components inside src/.
  4. Run any local preview workflow you use to validate styling (open the project in the browser or the host application that consumes src/ assets). If the repository is consumed by a build, ensure your new file is included by the build step that reads src/.
  5. Commit with a clear message referencing src/ and the feature (example pattern: "src: add -styles.css"). Include which files in src/ changed and why.
  6. When removing or renaming files in src/, update any import or build references immediately to avoid missing-assets in the small codebase.
